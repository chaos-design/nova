# T10 · 真实后端与持久化接入

- **优先级**：P2　**领域**：平台能力　**状态**：blocked（需产品决策形态与时机）
- **前置阅读**：`docs/architecture.md` 第 8 节「接入真实后端」、`AGENTS.md` §5 技术债表

## 问题

「无后端与持久化」派生出当前技术债表的五项，它们同源、应一并决策：

1. 交互状态刷新即失（无持久化）；
2. 报告导出走 `Blob` + `ObjectURL`，仅前端下载，无服务端归档；
3. 本地 Agent 无历史评测记录——只能进沙盒跑全新验证，无法查看对比
   （`docs/local-agent.md` 第 7 节已列）；
4. 沙盒剧本同步生成，单次超过 200 步会一次性生成长数组
   （后端化时可顺带改为按需产出）；
5. 真实执行器按 `LLM_*` 绑定单端点，多个内置端点并行时才需注册表驱动。

架构文档已写明接入路径：把 `mock-data.ts` 的导出函数换成真实请求，
`src/lib/nova` 之上的一切（页面、组件、hooks）不动。

## 决策点

- 后端形态：BFF（Next.js Route Handler 扩展）还是独立服务；
- 存储选型与部署环境；
- 评测结果是否入库、本地 Agent 的验证历史保留策略。

## 出口

决策后按 architecture.md 第 8 节的路径拆任务进入 `planning`；
在此之前不动任何数据层代码，避免为臆测的后端做抽象。
